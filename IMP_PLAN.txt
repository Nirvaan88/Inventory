# Role-Based Permissions & Approval Logic Updates

This document outlines the implementation plan to address the role-based UI and backend logic for the Issue Item Challan, Item Vendor Mapping Master, and the Item Master.

## Proposed Changes

### 1. Issue Item Challan Amount Population
**Goal:** Super admins should see the actual Amount based on the Item Vendor Mapping, while admins continue to see 0.
- **Backend API (`server.js`)**: Update the `GET /api/challan/detail` endpoint. After executing `sp_GetDetailDataChallan`, if the user is a Super Admin, the backend will fetch the original `ItemId`s from the `IssueItem` table and look up their latest `Total` price in the `ItemVendorMapping` table. It will then replace the `Rate` and compute the `Amount` (`Rate * Pcs`) in the response data.
- **Frontend (`pages-reports.js`)**: The frontend already sets the amount to 0 for admins. It will now properly render the enriched amounts for Super Admins.

---

### 2. Item Vendor Mapping Dashboard Columns
**Goal:** Hide the "Rs.", "GST(%)", and "Total" columns from the dashboard table for admin users.
- **Frontend (`pages-masters.js`)**: Update the `_renderIVM()` function. We will wrap the table headers (`<th>`) and table cells (`<td>`) for these three columns in a check (`!isAdmin()`). Super admins will see them; admins will not.

---

### 3. Pending Approval UI (Greyed Out Rows)
**Goal:** Items or Mappings created by an admin should be visibly greyed out until a super admin approves them.
- **Frontend (`pages-masters.js`)**: 
  - Update `_renderItems()` and `_renderIVM()`.
  - For rows where `ApprovalStatus === 'PENDING'`, we will apply a CSS style: `opacity: 0.5; background: #f9f9f9;` (or similar) to grey out the row.
  - We will add a `title` attribute to the row: `"Approval is pending, once done, it will be enabled."` so the user sees a tooltip on hover.
  - Admins will still be able to click the Edit button for these pending rows.

---

### 4. Conditional Edit Mode for Admin (Item Vendor Mapping)
**Goal:** Admins should only be able to edit Rs., GST, and Total if the item is newly added and pending approval.
- **Frontend (`pages-masters.js`)**: Update the IVM Edit Modal logic (`showIVMEditModal` or equivalent).
  - If the row is `ApprovalStatus === 'PENDING'`, the Rs, GST, and Total input fields will be visible and editable by the admin.
  - If the row is an existing, approved entry, these three fields will be completely hidden from the admin edit modal.
  - Super admins will always see and be able to edit these fields regardless of status.

## Verification Plan

### Automated Tests
- No new automated tests are required.

### Manual Verification
1. **Admin User**: 
   - Verify that adding a new Item Vendor Mapping greys it out in the table.
   - Verify hovering over the greyed-out row shows the "pending approval" tooltip.
   - Verify clicking Edit on the greyed-out row shows the Rs, GST, and Total fields.
   - Verify clicking Edit on an older (approved) row does NOT show the Rs, GST, and Total fields.
   - Verify the dashboard table does not show Rs, GST, and Total columns at all.
   - Generate an Issue Item Challan and verify Amount and Total are 0.
2. **Super Admin User**:
   - Verify the dashboard table shows the Rs, GST, and Total columns.
   - Verify that approving a pending mapping removes the grey-out effect.
   - Generate an Issue Item Challan and verify the Amounts are populated using the mapping's Total.
